# 2026-11-12 학습 기록 — Week 0 인프라 구성

## 오늘의 목표

백엔드 성능·장애 실험을 위한 로컬 인프라의 기반을 구성한다. 기존 MySQL 대신 익숙한 SQL Server를 사용하고, Docker Compose로 데이터베이스와 모니터링 서비스를 실행한다.

## 환경 및 구성

- OS: Windows / Docker Desktop
- Docker CLI: 29.3.1
- Docker Compose: v5.1.1
- SQL Server: 2022 Developer
- Prometheus: v2.55.1
- Grafana: 11.3.0
- Compose project: `backend-lab`

| 서비스 | 컨테이너 | 포트 | 확인 상태 |
|---|---|---:|---|
| SQL Server 2022 | `lab-mssql` | 1433 | `Up (healthy)` |
| MSSQL 초기화 작업 | `lab-mssql-init` | - | `Exited (0)` |
| Prometheus | `lab-prometheus` | 9090 | 컨테이너 실행 확인 |
| Grafana | `lab-grafana` | 3000 | 컨테이너 실행 확인 |

SQL Server 데이터는 Compose named volume `mssql-data`에 저장한다. Grafana 데이터는 `grafana-data`에 저장한다. 로컬 비밀번호는 `.env`에 두며 Git에 커밋하지 않는다.

## 오늘 직접 수행한 작업

1. Docker Desktop을 실행해 Docker Engine 연결 문제를 해결했다.
2. SQL Server 2022 Developer 이미지 기반 Compose 서비스를 구성했다.
3. `.env`에 SA 비밀번호를 설정하고 SQL Server 비밀번호 정책 오류를 해결했다.
4. MSSQL healthcheck를 통해 서버 준비 상태가 `healthy`인지 확인했다.
5. `mssql-init` 일회성 서비스로 `lab` 데이터베이스를 생성하도록 구성했다.
6. YAML 들여쓰기 오류(탭 문자)를 공백으로 수정했다.
7. Bash 스크립트가 `bash -c`에 하나의 인자로 전달되도록 Compose `command`를 배열 형태로 수정했다.
8. 초기 연결 지연에 대응하도록 MSSQL TCP 연결 재시도 로직을 추가했다.
9. 초기화 로그에서 `MSSQL is accepting connections`를 확인했다.
10. 초기화 컨테이너의 종료 코드가 `Exited (0)`인지 확인했다.
11. `sqlcmd`로 SQL Server에 접속해 `sys.databases`에서 `lab` 데이터베이스가 존재하는 것을 확인했다.

## 발생한 문제와 해결

### 1. Docker Engine 연결 실패

오류:
```text
failed to connect to the docker API
The system cannot find the file specified.
```

원인: Docker Desktop 엔진이 실행 중이지 않았다.

해결: Docker Desktop을 실행한 후 Docker CLI 연결을 복구했다.

### 2. SQL Server SA 비밀번호 정책 위반

원인: 최초 비밀번호가 SQL Server의 복잡도 정책을 충족하지 못했다.

해결: 로컬 `.env`의 비밀번호를 정책에 맞게 변경했다. 실제 비밀번호는 저장소나 학습 기록에 기록하지 않는다.

### 3. YAML 탭 문자 오류

오류:
```text
found a tab character where an indentation space is expected
```

원인: YAML 들여쓰기에 탭 문자가 포함됐다.

해결: 해당 서비스 설정을 공백 들여쓰기로 다시 작성하고 `docker compose config --quiet`로 구문을 검증했다.

### 4. Bash 초기화 스크립트 구문 오류

오류:
```text
syntax error near unexpected token `newline'
```

원인: 스크립트가 `bash -c`에 의도한 단일 문자열로 전달되지 않았다.

해결: `command`를 배열로 선언하고 블록 스크립트를 하나의 인자로 전달했다. 또한 `tcp:mssql,1433` 주소로 SQL Server 연결을 최대 30회 재시도하도록 구성했다.

## 검증 결과

초기화 로그:
```text
MSSQL is accepting connections
```

컨테이너 상태:
- `lab-mssql`: `Up (healthy)`
- `lab-mssql-init`: `Exited (0)`

데이터베이스 확인 명령:
```cmd
docker exec lab-mssql /opt/mssql-tools18/bin/sqlcmd -C -S localhost -U sa -P "비밀번호" -Q "SELECT name FROM sys.databases WHERE name = 'lab';"
```

결과:
```text
name
--------------------------------------------------------------------------------------------------------------------------------
lab

(1 rows affected)
```

따라서 SQL Server 실행, TCP 연결, 초기화 스크립트 정상 종료, `lab` 데이터베이스 생성까지 확인했다.

## 학습한 개념

- Docker Compose 서비스와 named volume
- `.env` 기반 환경 변수 관리 및 비밀 값의 Git 제외
- Healthcheck와 `depends_on: condition: service_healthy`의 역할
- 일회성 초기화 컨테이너와 종료 코드
- YAML 블록 스칼라, 들여쓰기 및 배열형 command
- 컨테이너 간 서비스 DNS 이름과 TCP 포트 연결
- Bash 반복문을 이용한 연결 재시도
- `sqlcmd`를 이용한 SQL Server 접속 및 시스템 카탈로그 조회
